# App 3.1.50 / 后台 3.1.50

## 本轮修复

- 待取件列表“确认收到”卡片可点击查看对应包裹详情；商品名只占一行，进入详情可展开全文。
- 订单基本信息增加当前运单号、派送员电话。同订单多运单分别展示，缺号不借用其他包裹；号码按当前物流中明确派送角色提取，客服、收件人、旧改派号码不作为派送员。
- 最新物流和展开轨迹中的完整手机号均可点击打开拨号界面。保留原文，脱敏号码、单号及取件码不转为电话；没有完整可靠号码时显示“未提供”。
- Android只打开系统拨号界面，不自动呼叫，不申请通话权限，不放开WebView外部导航。Enter/Space松键只触发一次，避免长按重复调用。关闭详情、返回、单包裹确认保持独立。

## 升级

App版本 **3.1.50 / 30150**，沿用原签名，可直接覆盖安装或在「我的 → 检查更新」下载。无需卸载、清数据或重新绑定。

后台 **3.1.50** 的业务逻辑沿用3.1.49，配套镜像内置本版App与更新清单。现有后台3.1.49也支持本轮App功能；更新镜像可让局域网下载新App。插件保持 **1.2.1**。

镜像 `ghcr.io/zsdd2/kdyzm:3.1.50` / `latest`，支持amd64、arm64。保留原数据卷、加密密钥及配置手动拉取重建。仓库发布不会自动更新NAS。

## 验证与边界

本轮开发回归：783项App、948项后台、295项Android测试通过；H5/Android构建和lint通过。合成数据在320、390、844宽度复测标题、详情、运单隔离、电话点击、键盘长按、返回还焦和逐件确认。发布前按相同完整门禁核验最终构建，公开源码与APK资源逐字节对照。

原生兼容动作 `dialPhone` 仅接受 `{phone}`，规范字符串为5–15位数字和可选前导`+`；UI按已保存的完整大陆手机号调用。Android在主线程重新检查可信页面后用`ACTION_DIAL`，不触碰订单状态。

实体手机拨号和覆盖安装未在本轮验收；H5的电话处理器由系统配置。未运行nightly扫描。平台没有提供明确派送员完整号码时不猜测或补造。
